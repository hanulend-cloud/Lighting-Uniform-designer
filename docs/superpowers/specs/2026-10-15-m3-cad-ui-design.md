# 3D 기구 모드 CAD식 UI 설계 — 점진 계산 · 결과 그래프 · 설계 점검

- 날짜: 2026-10-15
- 선행: `2026-10-14-3d-line-light-design.md`(3D 기구 모드), P1~P3 구현(기구·LED·관측면·3D MC·집계)
- 시안: `docs/mockups/m3-ui-mockup.html`(v2, 사용자 확인 — "레이아웃 괜찮음, 디테일은 이후 보완")
- 대상: **3D 기구 모드만**. 평판 모드 화면은 그대로 둔다.

## 1. 결정 사항 (사용자 확정)
- 3D CAD 에 익숙한 기구설계자 기준 화면이다. 명령 막대, 왼쪽 피처 트리와 속성, 가운데 3D, 오른쪽 결과 그래프로 구성한다.
- 3D 모델에는 광량을 간단히(관측면 색) 보이고, **2D 광량 분포와 1D 라인 프로파일(길이·폭)을 오른쪽 그래프로 항상** 보인다. 균일도와 광량의 목표 대비 현황은 그래프 옆에 둔다.
- 3D 는 회전, 확대·축소, 이동이 가능하다. x·y·z 축을 표시하고, **평면(XY)·정면(XZ)·측면(YZ)·등각** 보기 버튼을 둔다(평면·정면·측면은 정투영).
- 계산은 **자동 점진**이다. 값이 바뀌면 다시 시작하고, 1초마다 갱신하며, 잡음 목표에 도달하면 멈춘다.
- 항상 보이는 지표는 균일도(길이·폭 U)와 판정, 광 효율·휘도다.
- 설계 점검 4종: LED–부품 간섭, LED–커버 거리·도달, 살두께, 빛 새는 틈.
- 구현 방식은 바닐라 JS 모듈 분리다(`src/ui/m3/`, 무빌드 유지).

## 2. 화면 구성
| 영역 | 내용 |
|---|---|
| 명령 막대 | 기구 불러오기 · LED 지정 · 관측면 · 단면 · 맞춤(F) · 계산 일시정지/재개 · 단축키 안내(Esc 선택 해제) |
| 왼쪽 위: 피처 트리 | 부품(소재 배지) · 광원(LED STEP/직접 배치, 개수·피치) · 관측면(라인 종류·길이·폭) · 목표 · 접촉면. 클릭하면 3D 강조와 아래 속성 전환 |
| 왼쪽 아래: 속성 | 선택한 노드의 편집기만 표시(기존 부품·광원·관측 편집기를 노드별로 나눠 재사용) |
| 가운데: 3D 뷰 | three.js. 드래그 회전, 휠 확대, 우클릭·Shift 드래그 이동. 축 표시(원점 축 + 왼쪽 아래 회전 축 창). 보기 버튼 4개. 관측면 광량 색, LED 표시, 설계 점검 표식, 단면 평면 |
| 오른쪽: 결과 | ① 2D 광량 분포(관측면 펼침 s×w) + 평균 광량(목표 대비)·광 효율 ② 길이 방향 1D 프로파일(목표선) + 길이 U 게이지·판정 ③ 폭 방향 1D 프로파일(최저 창) + 폭 U 게이지·판정 |
| 아래: 상태 띠 | 신뢰도(잡음 ±%, 진행 막대) · 광자 수 · 설계 점검 배지 4개(클릭하면 3D 표식 강조) |

- 계산 전이나 무효 상태에서는 그래프 자리에 안내 문구를 둔다("관측면을 지정하세요", "광원을 지정하세요").
- 관측면 색지도: 관측면 메쉬 정점마다 (s,w) 를 구해 집계 지도 셀 값으로 색을 칠한다(최대 대비, 같은 색 막대).

## 3. 코드 구조와 데이터 흐름
- 새 폴더 `src/ui/m3/`.

| 파일 | 책임 |
|---|---|
| `store.js` | 저장 상태(`spec.mech3d`)와 세션 상태(선택, 선택 모드, 라인, 계산 진행·결과, 점검 결과)를 보관. `update(tag, fn)` → 변경 태그(`material`·`light`·`observe`·`target`·`contacts`·`view`·`session`)로 구독자에게 알림. 저장은 디바운스 |
| `app.js` | 3D 모드 화면 마운트, 저장소와 각 구성요소 연결, 키보드 단축키 |
| `command-bar.js` · `feature-tree.js` · `property-panel.js` | 화면 구성요소(기존 `mech3d-panel.js`·`mech3d-light-panel.js` 편집기를 노드별로 이식) |
| `results-panel.js` | 2D 분포, 길이·폭 프로파일(캔버스), 지표 카드 |
| `status-bar.js` | 신뢰도, 점검 배지 |
| `progressive.js` | 점진 계산 제어기(순수 로직 + Worker 포트 주입, Node 시험 가능) |
| `checks.js` | 설계 점검(순수 함수, Node 시험) |
| `colormap.js` | 관측면 정점 → (s,w) → 색(순수 함수) |

- 기존 `src/ui/mech3d-view.js` 는 확장한다: 보기 전환(정투영 카메라), 축 표시, 관측면 색지도 레이어, 점검 표식 레이어, 단면 평면.
- `main.js` 에는 3D 모드 진입·이탈 시 `m3/app.js` 의 mount/unmount 만 남긴다. 기존 3D 코드는 `m3/` 로 옮긴다.
- 흐름:
  1. 값이 바뀌면 `store.update(tag)` 가 실행된다.
  2. 태그에 따라 처리가 달라진다.
     - `material`·`light`·`observe`·`contacts`: 계산을 다시 시작하고 점검도 다시 돌린다(광원·기하에 해당할 때).
     - `target`: 판정만 다시 한다.
     - `view`: 그리기만 다시 한다.

## 4. 점진 계산
| 항목 | 설계 |
|---|---|
| 시작 | 물리 변경 후 0.5초 디바운스를 두고, 진행 중이면 토큰으로 무효화한 뒤 새로 시작 |
| Worker 장면 캐시 | 새 메시지 `scene` { sceneKey, mechParts, mspec, ledParts, lineData, G, obs, emitters } 로 Worker 가 장면·BVH 를 한 번 만든다. 이후 `chunk` { sceneKey, seed, N } 만 보낸다(N = Worker 당 25,000). 응답은 { sceneKey, acc, cnt, ledger, leak }. sceneKey 가 다르면 무시 |
| 누적 | 메인이 청크 결과를 배치 목록으로 모은다. 1초마다 `tallyStats`, 프로파일, 색지도, 지표를 갱신 |
| 중단 | 잡음(relNoise) ≤ 목표(기본 2%) 또는 광자 5백만이면 멈춤. 사용자 일시정지/재개 |
| 목표 변경 | 누적 데이터로 판정만 다시(계산 유지) |
| 격자·원뿔 변경 | 집계 격자가 바뀌므로 다시 시작 |
| 휘도 | LED 광속(lm/개)이 있으면 평균 휘도 = 총 광속 × 관측면 출사 비율 / (관측면 면적 m² × π) [cd/m², Lambert 가정, cone 90°]. 없으면 상대값(최대 대비 %) |
| 광 효율 | 관측면 원뿔 안 출사 / LED 총 광속 |
| 새는 빛 | 청크마다 관측면이 아닌 면으로 탈출한 빛을 (부품, 면) 별로 합산 → 점검 ④ 입력 |

## 4a. LED 선택·속성 (2026-10-20 추가, 사용자 확정)
- LED 를 부품처럼 선택한다: 3D 에서 LED 몸체·원뿔 클릭(선택 모드가 아닐 때) 또는 LED 노드 속성의 ◀ ▶. 세션 상태 `ledSel` = 현재 배치의 LED 번호.
- LED 속성 창(쉬운 말): 머리 `LED 3 · 10개 중 · 라인 위치 35.0 mm`; **배광(공통)** 버튼 [넓게 120°] [보통 90°] [좁게 60°] + 직접 입력(빛이 퍼지는 각도, 반치폭) — 120° 는 램버시안, 그 외는 가우시안으로 자동; **밝기(공통)** 광속 lm/개; **위치 — 전체 LED** 커버까지 거리(높이, 공통 dz)·배치(개수·피치·열); **위치 — 이 LED만** 라인 방향 Δs·높이 Δz(mm)·[원래대로]·(LED STEP) 제외/포함.
- 개별 조정 저장: `light.ledAdjust = { layoutKey, items: { [번호]: { ds, dz } } }` — layoutKey(배치 종류·개수·피치·열·간격)가 바뀌면 무효(알림 후 삭제). 적용: 직접 배치·가상 배치 = 그 LED 의 s 를 s+ds 로 다시 놓고(라인 접선 따라) 높이 dz; LED STEP 원래 = 그 LED 몸체·발광점을 접선 방향 ds·관측 방향 dz 로 평행 이동.
- 3D: LED 마다 짧은 반투명 원뿔(꼭짓점 = 발광점, 축 = 발광 방향, 반각 = 배광/2, 길이 = min(4 mm, 0.4 × 커버까지 거리)), 선택한 LED 는 주황 강조 — 기존 화살표 대체.

## 5. 설계 점검 (`checks.js`, 기하 점검은 변경 즉시, 새는 빛은 계산 결과로)
| 점검 | 방법 | 기준 | 3D 표시 |
|---|---|---|---|
| ① LED–부품 간섭 | 발광점이 다른 부품(PCB 제외) 안인지 광선 홀짝, LED 몸체 외곽 상자와 부품 삼각형 겹침(BVH 상자 질의 + 삼각형–상자 교차) | 간섭 있으면 실패 | 빨간 원 + 해당 LED |
| ② LED–커버 거리·도달 | LED 마다 지향각 안 64개 광선 → 처음 닿는 부품이 관측면 부품(또는 그 앞의 투과 부품)인 비율과 축 방향 거리 | 도달 < 50% 경고 | 거리선 |
| ③ 살두께 | 투과성 부품의 삼각형 중심에서 안쪽(−법선) 광선 → 같은 부품 반대 면까지 거리의 최솟값(면적 상위 표본) | < 최소 살두께(기본 0.8mm) 경고 | 얇은 곳 강조 |
| ④ 빛 새는 틈 | 점진 계산의 새는 빛 / 전체 탈출 | > 20% 경고(가장 큰 면 표시) | 새는 면 주황 |

- 점검 기준값(최소 살두께, 도달률, 새는 빛 비율)은 목표 속성에서 조정할 수 있다.

## 6. 검증
| 대상 | 방법 | 기준 |
|---|---|---|
| store·점진 제어기 | Node + 가짜 Worker 포트 | 재시작·취소·중단 조건, 목표 변경 시 재판정만, 이전 청크 무시 |
| 누적 동등성 | 같은 시드 목록의 청크 누적 = 일괄 계산 | 비트 일치 |
| 설계 점검 | 합성 형상 Node 시험 | 간섭·0.5mm 얇은 벽·가린 LED·새는 면 정확 검출, 정상 형상 오탐 0 |
| 색지도 매핑 | 관측면 정점 (s,w) 셀 값 = 집계 지도 | 일치 |
| 성능 | 샘플(기구+LED STEP 10개) | 첫 지표 ≤ 2초, 잡음 ±5% ≤ 10초 |
| 브라우저 | 실제 클릭 | 값 변경 → 자동 재계산, 보기 4종, 그래프 갱신, 점검 표식, 새로고침 복원, 평판 모드 복귀 |
